# MapTRv2 v4/v3 可选优化与验证

`maptrv2.datacontainer_pin` 和 `maptrv2.fused_adamw` 是独立开关，
在 `configs/recipe.yaml` 与交付的 `optimization.yaml` 中默认开启。
其余 MapTRv2 Group、训练配置、数据路径、worker 数量和模型算法不在此次移植范围内。

## 启用与回退

在目标 DTK/HCU 环境按需调整 recipe（把不需要的 Group 设为 `enabled: false`），
再按该 recipe 对干净模型仓库执行 `turbo-physai optimization generate --force` 重新生成。
生成的配置绑定实际 PyTorch、MMCV 和模型目标的源码证据；`--force` 只允许覆盖已存在的
输出，不绕过 commit、干净工作区或目标符号检查。源码证据只证明挂接点身份，
不证明 Apex 内核精度或速度。

交付配置中的两项新增证据采集自 CPU PyTorch 2.14.1 和 MMCV 1.7.2。
优化器证据来自实际 MMCV `build_optimizer`（模型训练模块从 `mmcv.runner` 导入此函数）。
这些记录不代表 DTK/HCU 环境已验收；目标版本不同仍须重新生成配置。

```bash
turbo-physai optimization generate \
  --recipe /path/to/recipe.yaml \
  --repo /path/to/MapTRv2 \
  --commit e03f097abef19e1ba3fed5f471a8d80fbfa0a064 \
  --output /path/to/optimization.yaml

turbo-physai run \
  --optimization-config /path/to/optimization.yaml \
  --runtime-config turbo_physai/optimizations/models/maptrv2/configs/runtime.yaml \
  python tools/train.py projects/configs/maptrv2/maptrv2_nusc_r50_24ep.py
```

通过独立的 `enabled` 字段关闭优化并重启训练进程。没有额外环境变量或隐式 fallback。
v4 关闭后是现有 PhysAI DataLoader 行为；v3 关闭后使用普通 AdamW。
已创建的优化器实例不会因引擎恢复函数而改变类型；回退必须重启并重新构建优化器。

## v4：DataContainer 后台 pin

- 只包装原生 pin-memory 入口，不替换 DataLoader，不在模块导入时安装 patch。
- `cpu_only=True` 内容保持 CPU 原样；其他 DataContainer 保留属性，递归处理数据。
- 普通容器交给原生实现；已 pinned 和非 CPU 张量直接返回。识别参考 v4 同类 patch，避免双重包装。
- 直接包装受支持 PyTorch 版本的 `torch.utils.data._utils.pin_memory.pin_memory` 入口；目标解析和源码信任检查由引擎负责。
- `pin_memory=False` 不会被强制打开；`num_workers=0` 没有后台线程重叠。
- 后台 pin 仍有复制成本；监控主机内存，尤其是高 worker/预取配置。

## v3：Apex FusedAdamW 与断点

只包装 MapTRv2 训练模块的 `build_optimizer` 引用；不替换全局 AdamW 注册。
调用原 MMCV 构建流程，保留 `paramwise_cfg`、参数顺序和参数组超参数。
Apex 延迟加载，使用独立注册名 `TurboPhysAIMapTRv2FusedAdamW`；同名异实现明确报错。

支持具备 `amp_C.multi_tensor_adam` 的 Apex 非 capturable、组级 step 实现，以及
FP32 参数上的 AMP。纯 FP16/BF16 参数、master weights、AMSGrad、maximize、
differentiable、关闭 bias correction、稀疏梯度及显式指定其他 fused/foreach 后端
不在此适配器范围内。未知 Apex step 格式在构建时被拒绝。

保存时输出普通 PyTorch AdamW 格式：每个有状态的参数保留 `step`、`exp_avg` 和
`exp_avg_sq`，移除 Apex 组级 clock。关闭 v3 后普通 AdamW 可直接加载这些新断点。
加载时复制并验证状态，将同组一致的参数步数转换为 Apex 组步数，保留动量和超参数。
同组已有参数的步数不一致、动量形状/dtype 不兼容、参数组数量或长度不同会明确报错，
不会重置、取最大步数或修改断点文件。

未使用/冻结参数可以保持无状态，整组没有梯度不推进时钟。已经初始化的组成员不能在
其他成员更新时单独缺梯度；之前未使用的参数也不能在组时钟推进后才开始更新。
这两种情况会在参数更新前报错，应使用普通 AdamW 或把参数拆成独立组。
这是组级 bias correction 与逐参数 AdamW 语义的限制。MMCV paramwise 构造的单参数组
不受同组部分缺梯度限制。已保存的普通格式断点仍可回退给 PyTorch AdamW。

原生 Apex 只提供组级 step 的旧断点也可在 v3 开启时加载；关闭 v3 前先通过适配器
加载并保存一次普通格式断点。仅有组时钟的旧 Apex 文件不能直接交给普通 AdamW。

实现契约依据 [Apex FusedAdam 源码](https://github.com/NVIDIA/apex/blob/master/apex/optimizers/fused_adam.py)
与 [PyTorch pin-memory 线程源码](https://github.com/pytorch/pytorch/blob/v2.6.0/torch/utils/data/_utils/pin_memory.py)。
目标厂商 Apex fork 必须通过运行时契约检查及设备测试。

## 功能测试

v4 与 v3 的专项功能测试位于仓库级 test/optimizations/，主要覆盖 DataContainer 递归 pin、Apex 优化器状态转换、断点回退及开关组合。真实 pinned allocator/DataLoader 和 Apex fused kernel 场景标记为 hcu、model_deps。

在目标环境运行 bash scripts/test_maptrv2.sh；CPU 逻辑测试运行 bash scripts/test_maptrv2.sh -m 'not hcu and not model_deps'。
